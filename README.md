# Digital CookBook

Turn Instagram and TikTok cooking videos into a browsable, tagged recipe book.

See a reel you like → tap **Share** → the app fetches the caption, asks an LLM to pull
out the title, ingredients (with quantities) and steps, and saves it with a link back to
the original video. Later, open the app and browse your recipes by tag to actually cook.

- **App:** https://digital-cookbook.omergrinwald14.workers.dev
- **API:** https://digital-cookbook-api.onrender.com

Built as a learning project, in small reviewed steps — the full roadmap lives in
[PLAN.md](PLAN.md).

## Features

- **Import from a link** — Instagram reels and TikTok videos; the caption is parsed into
  structured ingredients and steps. Unreadable or caption-less posts are still saved,
  just with empty fields.
- **Add your own** — type a recipe by hand and attach a photo, no video needed.
- **Tags** — create your own tag list; the LLM picks from it and can't invent new ones.
  Filter the recipe list by tag, search by title, ingredient or tag name.
- **Favorites and "Up next"** — flags for the recipes you cook often or plan to cook.
- **Edit anything** — title, ingredients, steps and tags are all editable after import.
- **Share with family** — send a recipe to another user by email; they get it in a
  "Shared with me" inbox and can accept it into their own book or dismiss it.
- **Installable PWA** — on Android it registers as a share target, so the phone's native
  Share sheet lists CookBook alongside WhatsApp. Shares made offline are queued and sent
  when the connection returns.

## Stack

| Layer | Tech | Why |
|---|---|---|
| Backend API | Python 3, FastAPI, uvicorn | the import pipeline + REST endpoints |
| Video metadata | [Apify](https://apify.com) Instagram / TikTok scrapers | handles logins and cookies for us |
| Parsing | Google Gemini (`gemini-2.5-flash`) | caption + tag list → structured recipe JSON |
| Database + storage | Supabase (Postgres + object storage) | recipes, tags, users, thumbnails |
| Frontend | Vanilla HTML/CSS/JS, PWA + service worker | no build step, installable on phones |
| Hosting | Render (API) + Cloudflare Workers (static frontend) | free tiers, auto-deploy on push to `main` |

## How it works

```
Instagram / TikTok URL  (Share sheet, or pasted into the app)
        │
        ▼
  FastAPI backend
   1. Apify   → caption + thumbnail + video link
   2. Gemini  → caption + your tag list → { title, ingredients[], steps[], tags[] }
   3. Supabase→ save the recipe (duplicate source URLs are de-duplicated)
        │
        ▼
  PWA frontend → browse / filter / edit / share
```

## API

All endpoints take an `X-User` header with the caller's email — a deliberately light
identity model (see below).

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | health check |
| `POST` | `/import` | `{ "url": ... }` → fetch, parse and save a recipe |
| `GET` | `/recipes` | list recipes (optionally filtered) |
| `POST` | `/recipes` | create a recipe manually |
| `PATCH` | `/recipes/{id}` | edit title, ingredients, steps, tags, favorite, up-next |
| `DELETE` | `/recipes/{id}` | delete a recipe |
| `POST` | `/recipes/{id}/photo` | upload a photo for a manual recipe |
| `GET` `POST` `DELETE` | `/tags` | manage the tag list |
| `POST` | `/recipes/{id}/share` | share a recipe with another user |
| `GET` | `/shared` | pending recipes shared with me |
| `POST` | `/shared/{id}/accept` \| `/dismiss` | resolve a shared recipe |
| `GET` `POST` `DELETE` | `/friends` | manage the people you share with |
| `POST` `DELETE` | `/users` | register / remove a user |

Interactive docs are generated by FastAPI at `/docs`.

## Running locally (Windows)

Prerequisites: Python 3.11+, and API keys for Apify, Gemini and Supabase.

```powershell
# 1. Backend dependencies
cd backend
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Create `backend/.env`:

```
APIFY_TOKEN=...
GEMINI_API_KEY=...
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_KEY=...
```

```powershell
# 2. Run the API (from backend/)
uvicorn app.main:app --reload
```

```powershell
# 3. Run the frontend in another terminal (from the repo root)
py -m http.server 5500 -d frontend
```

Then open http://localhost:5500. Point the frontend at your local API by editing the
`API_BASE` constant at the top of [frontend/app.js](frontend/app.js).

The database schema (tables `recipes`, `tags`, `recipe_tags`, `users`, `friends`,
`shared_recipes`, plus a public `thumbnails` bucket) is managed by hand in the Supabase
SQL editor; the shape of each table is documented in [PLAN.md](PLAN.md).

## Deployment

Push to `main` and both halves redeploy automatically: Render builds the backend from
`render.yaml` (~2–4 min), Cloudflare publishes `frontend/` from `wrangler.jsonc` (~1 min).
Secrets are set by hand in the Render dashboard, never committed.

## A note on auth

This is a family app, not a public product. "Login" is just an email stored in the
browser and sent as an `X-User` header — the threat model is *typos*, not attackers.
Everything is scoped per user by that email, so swapping in real authentication later
means changing one function (`current_user` in `backend/app/main.py`) and nothing else.
